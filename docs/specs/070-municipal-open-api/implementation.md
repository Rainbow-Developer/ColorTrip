## 구현 규모 / 단위 분할

- **규모 판단**: 계획 단계에서는 단위 분할을 예정했으나, 실제 구현해보니 7개 통계가 하나의 응답·하나의 서비스 함수로 자연스럽게 묶여 한 번에 구현·검증하는 편이 더 간결했다(라우터·서비스 파일을 쪼개는 이득보다 리뷰 응집도가 더 중요하다고 판단).
- **구현 단위** (실제로는 한 커밋으로 묶어 구현):
  - [x] 1) `open_api_keys` 테이블·마이그레이션 + 키 발급 스크립트 + `serviceKey` 인증 dependency
  - [x] 2) 방문 인증 통계 + 월별 추이 + 인기 관광지 랭킹 + 인증 방식별 참여율
  - [x] 3) 여행자 성향(DNA) 분포 + 여정 완주 통계
  - [x] 4) 공유 통계 — `shares.region_id` 컬럼 추가(공유 생성 시점의 최다 완료 지역을 스냅샷) + 지역별 집계

- [x] `GET /api/v1/open/regions/{region_slug}/stats?serviceKey=...&months=6` — 7개 통계 전부 포함, 존재하지 않는 지역은 404
- [x] `shares.region_id`(nullable FK) 추가 + `create_share_card`가 완료 수 최다 지역을 대표 지역으로 저장
- [x] 로컬 백엔드로 실제 검증: 퀘스트 완주 → 여정 완료 → 공유 생성 후 실제 API 호출로 방문/인기 관광지/DNA 분포/여정 완주율/인증방식/공유 통계 전부 확인
- [x] 테스트(`tests/test_open_api.py`): 정상 조회, 키 누락/오류/회수 시 401, 존재하지 않는 지역 404 — 4건 전부 통과
