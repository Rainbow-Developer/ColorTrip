## 배경 / 목적

공개 출시 전에 이용약관·개인정보 수집 동의의 전문과 증빙을 실제 처리 흐름에 맞추고, 마케팅
동의·공개 이미지 URL·탈퇴 뒤 인증 사진 보관으로 생기는 개인정보 처리 불일치를 해소한다.

## 목표 (Goals)

- `terms-v2`, `privacy-v2`의 전문·시행일·다이제스트를 공개하고 동의 기록과 결속한다.
- 만 14세 미만 가입을 클라이언트와 서버에서 모두 차단한다.
- 마케팅 동의와 탈퇴 뒤 원본 사진 보관을 제거한다.
- 사진 원본을 공개 URL이 아닌 내부 객체 키로 관리할 기반을 마련한다.

## 비목표 (Non-Goals)

- 수익화·광고·푸시 발송 기능 도입
- 만 14세 미만 법정대리인 동의 흐름
- 운영자 법적 정보·Gemini/GCP 계약 정보가 미확정인 상태의 공개 출시

## 요구사항

- 기존 계정은 출시 전 테스트 계정임을 운영자가 확인한 경우에만 `prelaunch_migration` 출처로
  v2 동의를 적용한다. 외부 사용자가 있으면 이 migration을 실행하지 않는다.
- 생년월일은 필수 프로필 정보로 탈퇴까지 보관하되, 가입·수정 시 만 14세 이상이어야 한다.
- 실패 인증 사진은 판정 뒤 삭제하고, 성공 인증 사진과 프로필 사진은 탈퇴 시 삭제한다.

## 설계 개요 / 접근 방식

법적 문서 원본과 metadata를 `app/legal`에서 단일 관리하고, 인증 서비스가 같은 metadata의
version·digest를 `user_consents`에 저장한다. Flutter는 두 전문을 별도 공개 URL로 연다.
사진은 DB에 내부 object name을 저장하고 API 응답에서만 접근 URL을 발급하도록 단계적으로
전환한다.

## 의사결정 (함께 논의 · 근거 필수)

| 결정할 항목 | 선택지 | 제안 / 근거 | 상태 |
|------|--------|------------|------|
| 기존 테스트 계정 | 재동의 / 자동 적용 | **자동 적용**. 아직 공개 출시 전이라는 전제에서 UX를 유지하되, 사용자 체크 동의와 구분되는 `prelaunch_migration` 출처를 남긴다. | 합의됨 |
| 마케팅 동의 | 유지 / 제거 | **제거**. 발송 채널·철회 기능이 없어 동의만 수집할 목적이 없다. | 합의됨 |
| 탈퇴 뒤 사진 | 원본 보관 / 삭제 | **삭제**. 원본 사진은 단순 FK 분리만으로 익명화할 수 없으며, 집계 통계만 남긴다. | 합의됨 |
| 미성년 처리 | 법정대리인 동의 / 가입 제한 | **만 14세 미만 가입 제한**. 현재 보호자 동의 기능이 없어 제한이 최소 구현이다. | 합의됨 |
